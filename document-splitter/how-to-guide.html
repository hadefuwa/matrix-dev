How To Guide

How to tag your source document

The Document Splitter reads a single Word .docx file and turns it into every output automatically. The tool knows what to do with each piece of content because you mark it up with simple tags directly inside the Word document.

3 block types 1 required tag per block 4 media reference tags
The basics

How the tool reads your document

Your Word document is one long file. The tool scans it from top to bottom looking for opening and closing tags — pairs of angle-bracket markers like <HTML> and </HTML>. Everything between a matching pair is treated as a single block and turned into its own output file. Anything outside a recognised tag pair is ignored — it is treated as planning notes or context for the author.

i

Good to know You can mix worksheets, HTML pages, and documents freely in any order. The tool handles them all in a single pass. There is no limit on how many blocks a document can contain.

Everything up here is ignored by the tool.
You can write notes, planning, context — anything you like.

<HTML>
<filename>"CP4807-H1.html"</filename>
This is the content of Homework 1. It will become an HTML file.
</HTML>

More planning notes here — also ignored.

<worksheet>
<filename>"CP4807-1.doc"</filename>
This is Worksheet 1. It will become a Word-compatible file.
</worksheet>
Block types

The three block types

There are exactly three block-opening tags. Each one tells the tool what kind of output to produce. Choose the one that matches what the content is for.

<HTML> … </HTML>

Learner-facing web page. Use for homework tasks, assessment briefs, teacher notes, or any content that should be delivered as a web page.

→ .html / .htm file

<worksheet> … </worksheet>

Printable worksheet. Use for step-by-step practical tasks, lab activities, or any content students will work through on paper or screen as a document.

→ .doc / .docx file

<document> … </document>

Reference or supporting document. Use for certificates, data sheets, specification documents, or any standalone file that is not a worksheet or web page.

→ .docx file
!

Tags are case-sensitive <HTML> must close with </HTML> — not </html>. <worksheet> must close with </worksheet>. <document> must close with </document>. A mismatched case means the block will not be recognised.

Required tag

The <filename> tag — required in every block

Every block must contain exactly one <filename> tag. This is how the tool knows what to call the output file. The filename goes between the tags, wrapped in double quotes. 

<HTML>
<filename>"CP4807-H1.html"</filename>
Content goes here…
</HTML>
  • Always include a file extension — e.g. .html, .htm, .doc, .docx.
  • Wrap the filename in straight double quotes — "filename.html" — not curly/smart quotes (" ") which Word sometimes inserts automatically.
  • Filenames must be unique across the whole document — two blocks with the same filename means the second will overwrite the first.
  • Do not use spaces in filenames. Use hyphens or underscores instead — e.g. CP4807-marking-scheme.htm not CP4807 marking scheme.htm.
  • Do not use a block without a <filename> tag. The tool will flag it as a warning and cannot produce the output file.
i

Word autocorrects your quotes When you type "filename.html" in Word, autocorrect often changes the straight quotes to curly ones. Go to File → Options → Proofing → AutoCorrect Options → AutoFormat As You Type and uncheck "Straight quotes" with "smart quotes" before writing your filename tags.

Media references

Referencing media inside a block

If your content needs images, videos, audio files, or data sheets, reference them by filename using a media tag inside the block. The tool will match these references against the media files you upload alongside your document.

<image> … </image>

A photograph, diagram, or illustration. Supports JPEG, PNG, GIF, SVG, and WebP.

<image>traffic-lights.jpg</image>

<video> … </video>

A video clip. Supports MP4, WebM, and MOV.

<video>intro.mp4</video>

<audio> … </audio>

An audio file. Supports MP3, WAV, and OGG.

<audio>narration.mp3</audio>

<datasheet> … </datasheet>

A reference PDF or data sheet linked as a download.

<datasheet>spec-sheet.pdf</datasheet>
i

Two ways to supply media If you embed images directly into your Word document, the tool will extract them automatically — no ZIP needed. If you keep media files separately (e.g. high-resolution photos, videos), upload a .zip containing all the files via the media dropzone. The tool checks your embedded images first, then the ZIP.

<HTML>
<filename>"CP4807-H1.html"</filename>

Homework 1: Traffic lights design brief

Look at the circuit diagram below and answer the questions.

<image>traffic-lights.jpg</image>

Watch the video introduction before starting:

<video>intro.mp4</video>

</HTML>
Common mistakes

Things to watch out for

These are the most common issues found in source documents. The tool will warn you about all of them, but it is quicker to get them right from the start.

Blocks broken

Opening a block with two block tags at once

Starting a block with <HTML> <worksheet> on the same line confuses the tool — it cannot be both at once. The tool will flag a warning and pick one, but the result may not be what you intended. Fix: delete the tag you do not want.

Files overwritten

Two blocks sharing the same filename

If two blocks both have <filename>"CP4807-1.doc"</filename>, the second will silently overwrite the first in the output. Fix: give each block a unique filename — for example CP4807-prep.doc and CP4807-1.doc.

Output unnamed

Missing file extension in <filename>

A filename without an extension — "CP4807-cert" — leaves the tool unable to determine the file type. It will flag a warning and make a best guess, but the output may not open correctly. Fix: always include the extension — e.g. "CP4807-cert.docx".

Parser mismatch

Curly/smart quotes in <filename> tags

Word's autocorrect replaces " with " and ". These look similar but are different characters and some parsers will not read them as valid delimiters. Fix: disable smart quotes in Word's AutoCorrect settings before writing filename tags, or do a find-and-replace after writing the document.

Block not found

Wrong case on closing tag

<HTML> closed with </html> will not match. <Document> and <document> are also treated as different tags. Fix: make sure the opening and closing tag use exactly the same capitalisation.

Media missing

Media reference with no matching file

If you write <image>photo.jpg</image> but the file is not embedded in the DOCX and is not in the uploaded media ZIP, the tool will warn you that the file is missing and the output will have a broken reference. Fix: make sure every referenced media file is either embedded in the Word document or included in your media ZIP.

What you get

Understanding your output files

When you click Build Outputs and download the bundle, you receive a single ZIP file containing everything the tool produced from your source document. Here is what is inside and what each file is for.

HTML pages

Each <HTML> block becomes a self-contained web page. Open it in any browser to see formatted learner content — headings, lists, tables, images, and links all preserved from your Word document.

outputs/html/

Word documents

Each <worksheet> and <document> block becomes a .docx file. Styles, numbering, tables, and images from the source block are carried across and the file opens in Microsoft Word or Google Docs.

outputs/docx/

SCORM package

If your source document contains SCORM notes, a ready-to-upload imsmanifest.xml and package structure are generated alongside your HTML files. Upload the ZIP directly to Moodle, Canvas, or any SCORM-compatible LMS.

scorm/
i

Media files travel with the outputs Any images embedded in your Word document, or matched from your media ZIP, are copied into a media/ folder inside the bundle. HTML pages reference them using relative paths, so they display correctly when the bundle is extracted and served from any web server or LMS.

i

Your source files are preserved The bundle includes a source/ folder containing the original .docx you uploaded and, if you provided one, the companion media .zip. This means the bundle is self-contained — you always have the inputs alongside the outputs.

i

The bundle is the deliverable You do not need to do anything to the individual files before uploading. Extract the ZIP, and the folder structure is already correct for deployment. HTML files link to their media, the SCORM manifest points to the right launch file, and Word documents are standalone.

Folder structure inside the bundle

your-document-bundle.zip
├── source/
│   ├── CP4807-Introduction.docx  ← your original source document
│   └── Media.zip                 ← your media ZIP (if uploaded)
├── generated/

│   ├── CP4807-H2.html
│   ├── CP4807-1.docx             ← from <worksheet> blocks
│   └── CP4807-CPDcert.docx       ← from <document> blocks
├── media/
│   ├── traffic-lights.jpg        ← matched media files
│   └── intro.mp4
├── imsmanifest.xml               ← only present if SCORM detected
├── summary-report.txt
└── blocks-metadata.json
